# Signed local-only bootstrap and committed-context recovery candidate

The current provisioner gates all local file/owner work behind the broker execution gate. This candidate preserves that original entrypoint unchanged and appends a separate provision_disabled_owner operation requiring LocalApproval. An independent HMAC root must sign an exact local-only grant for account/release/policy, application/adapter/journal/private-parent paths, seed, current source lease and prepared-state fingerprint. The grant expires within 60 seconds and explicitly denies order transport and production execution. The real hard order gate must stay closed throughout local provisioning.

The original strict scan of one fresh unsent preparation, signed evidence/binding, current lease/cursor, paused controller and zero attempts/receipts is reused. Grant validity/trust is rechecked around commit checkpoints. Generated authority keys differ from capture and issuer keys; the issuer cannot be the broker token. Private approval proof is persisted with the local intent. Existing context directories block a new-key retry after interruption. Owner commit remains in the existing attached database transaction; no broker transport is called.

Local read-only recovery verifies the exact approved context digest, private file hashes/permissions, same identities/source bindings and committed signed owner. It requires the unsent PREPARED seed and zero attempts/receipts, never creates another key/owner, and refuses implicit rebinding to a restarted source lease. A new-lease migration and the actual configured worker bootstrap handoff still require implementation/qualification.

The 19 new VM cases include local enrollment with the actual hard gate unchanged, default old-gate rejection, wrong binding/signature/expiry/capture-root rejection, precommit interruption and duplicate-key retry blocking, expiry/revocation rollback, postcommit same-key recovery, and changed-lease recovery rejection. A separate seed preflight validates the changed candidate dependency chain. Positive local cases DO NOT override port.require_live_clearance; all account/private files and databases are synthetic fixtures. Network is denied by the test conftest.

Default CLI only stages code and runs tests against disposable state. It has no live enrollment/provisioning/apply action. No live trust root or authority is created; real controller and databases remain unchanged. No broker request is sent. Candidate code, not production bootstrap readiness, is the result. The existing provisioner AST and execution-port bytes are verified unchanged, and all candidate dependency pins are reconciled. Local validation is syntax/ZIP only; behavior runs on the user VM.

V2 corrects only the wrong-binding test fixture: the grant is deep-copied, a changed state fingerprint remains a valid 64-character digest, and the altered grant is signed by the synthetic issuer. This isolates exact binding rejection from signature/schema rejection. Runtime validation code is unchanged.
