# V2 alignment setup + dual exit: separate historical replay

This bundle adds a fourth selection in the Hilega Historical Replay page:
**V2 — alignment setup + dual exit (research)**.

It does not alter the selected live strategy, live V2 adapter, Sandbox worker,
orders, quantities, service configuration, frozen 490-session data or the forward
confirmation cohort. Existing Live/V1/V2 selections continue through their current
routes. Research artifacts are loaded from a separate directory, not generated by
an API request. The installer makes guarded, idempotent patches to the supplied
historical API and frontend and backs up existing files before installing.

## Installation

Place the downloaded ZIP in `~/RB-ITOS-AI`, then run:

```bash
cd ~/RB-ITOS-AI
source .venv/bin/activate
unzip hilega_v2_alignment_dual_exit_replay_bundle.zip
python hilega_v2_alignment_dual_exit_replay_bundle/install.py &&
./scripts/restart.sh &&
./scripts/status.sh
```

Restart is needed for the API to load its new historical route. The restart is a
user operation; the installer itself does not restart any service or arm execution.
On failure the installer restores source files. If a frontend build was started,
rebuild the restored frontend before restarting. An unexpected patch anchor stops
installation before mutation; do not edit the anchor blindly.

Open Hilega Historical Replay, select the new research strategy, then October 5,
6, 7, 8 or 9. These five reconstructed research sessions are included, so no
publisher command is needed for initial inspection. They are preserved if a file
already exists in the dedicated research directory.

## Rules implemented

1. Existing V1 accepted setup OR alternative completed-five-minute ordering:
   bullish RSI9 > EMA3 > WMA21; bearish RSI9 < EMA3 < WMA21.
2. Alternative signal also requires positive provisional directional gap and
   expansion versus the exact previous minute. No above/below-50 rule is added.
3. One alternative signal per continuous alignment episode. Breaking alignment
   resets eligibility. An existing pending setup is not overwritten by a new
   alternative each minute; the ten-minute window is not reset.
4. Retain the tested V2 gate: current and previous eligible directional WMA
   strength >=0.75, later arm confirmation, positive gap, exact consecutive-minute
   expansion >0, ten-minute window and no active actual position.
5. The retained exit-boundary exception permits a qualifying replacement after
   actual closure, using current/previous strength. It cannot bypass ownership.
6. Completed-five-minute RSI9 opposite WMA21 starts a diagnostic warning.
   Actual exit requires BOTH RSI9 and EMA3 on the opposite side of WMA21 in the
   current completed snapshot. Equality waits. Prior warnings alone do not exit.
7. Force any open actual position closed at exact 14:55 minute open. No new entry
   decision at or after 14:55. Entry uses the qualifying completed minute close;
   structural exit uses completed-five-minute close. Times displayed are IST
   decision availability, separate from candle labels.
8. EMA3/WMA21 are on RSI9, which is on Nifty closes. No EMA10 exit, mandatory WMA
   slope, minimum expansion >=0.25, fixed stop-loss, target or PCR filter was added.
9. Ordering is setup context; provisional directional alignment at later entry
   remains diagnostic under the tested V2 gate. There is no newly added mandatory
   RSI9/EMA3 directional slope at actual entry. The signal window may outlive a
   temporary loss of ordering; original canonical exits cancel same-side pending
   setups. Actual dual-exit ownership remains independent of canonical ownership.

## Inspection

The page shows exact rules and evidence provenance, daily Nifty metrics, trade
entry/exit prices and times, first RSI warning, MFE and giveback. Every completed
minute has an audit row, even without a pending signal. Expand View conditions for
completed-five-minute/provisional values, previous/current RSI/EMA/WMA, strength,
gap and delta, arm time, confirmation-window checks and reasons. Five-minute rows
also show RSI/EMA/WMA changes and actual exit confirmation. Active replay position
and mark-to-close Nifty points are shown per checkpoint. Exit then replacement
entry are ordered separately within a checkpoint's transition list. A filter
shows five-minute closes and trade transitions only.

Signals/denied count pending setup attempts, including cancelled or expired
attempts, not only completed trades. Reconstructed state is not a recorded live
signal ledger. MFE uses minute highs/lows from entry availability through before
exit availability and therefore may represent an intraminute maximum.

## Future replay publication (offline only)

Inputs must be `YYYY-MM-DD.json` caches with timestamped OHLC candles. Every minute
09:15–14:54 and the exact 14:55 open are mandatory. Duplicate/naive timestamps,
missing strategy minutes and insufficient indicator warmup are rejected.

```bash
PYTHONPATH=backend:. python scripts/publish_hilega_v2_alignment_replay.py \
  --dates 2026-10-06 2026-10-08 \
  --cache-root data/recovery/october-2026/nifty-cache \
  --warmup-root data/historical-evidence/hilega-milega-underlying-cache-v1 \
  --confirm PUBLISH_RESEARCH_ONLY
```

This explicit command replaces ONLY requested research session artifacts in the
new namespace. Using a different warmup source can produce different indicators.
To reproduce the included sessions' exact warmup, additionally supply
`--warmup-journal` with the October 9 journal extracted from the supplied evidence
archive. The publisher makes no broker request. Do not use live audit rows as
synthetic historical prices. Custom output-root must use the separate research
namespace leaf `hilega-v2-alignment-dual-exit-v1`.
