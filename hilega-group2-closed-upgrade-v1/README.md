# Combined closed Group 2 upgrade

Default check: verifies the supplied proposal and prior native recovery receipt; rechecks installed recovery; runs eight file-transaction tests including interrupted replacements and external-edit rejection; runs the actual sealed candidate worker twice under a new disposable user systemd unit with network address families restricted to AF_UNIX and no broker environment; verifies the proposed new recovery unit syntax; creates an exact 30-minute upgrade plan plus a current MILESTONES.md. Existing 74-case tests are reused, not rerun. Local validation is syntax and ZIP integrity only; behavior runs on the user VM.

Check command arguments: --repo, --proposal, --proposal-sha256. Apply/status/rollback require --repo --action ACTION --plan ABSOLUTE_PLAN --approve-plan-sha256 EXACT_DIGEST. Never use the proposal digest as plan approval. Check does not change application services; it starts only its named disposable systemd unit.

Apply keeps the execution factory disabled. It locks maintenance, requires exact paused/empty state, stops all six services, verifies no repository writers, backs up databases/code/wrapper/recovery and supervisor bindings privately, seals the new candidate, replaces only the wrapper and recovery service, installs the new exact recovery config/script, starts pause recovery before applications, and checks stable healthy services and the empty closed baseline. No database restore, cursor rewind, broker timestamp correction, authority provisioning, or enrollment is performed.

If apply fails, application services are held stopped; use this package's explicit rollback after reviewing the error. Rollback validates complete backups and accepts only old/new file hashes, restores old wrapper/recovery service, retains new immutable artifacts for audit, starts the prior closed runtime, and never restores databases. Changed external files block rollback. Interrupted backups before any replacement permit returning to unchanged old code. A failed/rolled-back upgrade is not automatically retried; retained destination conflicts require a reviewed recovery plan.

After successful apply use THIS tool's status command and its PLAN.json; old recovery/group1 status commands remain bound to the previous release and will reject the upgraded wrapper. The new plan folder contains ACTIVE-RUNTIME.json. No old approval receipt is rewritten. Full service-level crash/fault coverage and actual deployed rollback are not claimed by the eight file-transaction tests. The package's passing check certifies only its listed checks, not production readiness.

Milestone checkboxes are updated in the plan folder after a passing check and each successful apply/status/rollback. Previously completed evidence is labelled separately from pending deployment and live-readiness work.
