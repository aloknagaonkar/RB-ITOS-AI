# Candidate worker boundary + independent managed deadline integration

Stages from the passed admission/enrollment candidate review. Adds default-off runtime/window_worker_bridge.py and wraps native default_worker_poll after its original logic. No config means unchanged dispatch without private reads. Explicit private config binds release, application/adapter, journal, pin, state and receipt paths. Real hard order gate is checked closed before private config reads. The hook observes ONE post-window prepared source record, uses native pause, verifies unsent prepared request and zero attempts/receipts in the same pinned account, and signs a disabled seed-boundary receipt with the local capture key. It does not create an admission grant, durable enrollment handoff, authority or owner. A seed-boundary receipt is not enrollment authorization.

Native controller resume/pause and managed guards are restricted to explicit disposable workspace markers. Rehearsals reuse the previously VM-qualified Package A/managed-recovery native adapters. New arm/pause shared flock serializes guard recovery against resume; guard-loss intent is persisted under the same lock. Deadlines use wall clock plus a monotonic bound. Guard checks source lease, clock rewind, deadline and preparation count; systemd ExecStopPost invokes native pause after guard loss. No gate override.

Four actual process scenarios run on the VM: fresh synthetic post-resume signal through exact bundled outer launcher, signed worker seed boundary and reservation plus restart replay; native normal timeout; initiator SIGKILL with guard surviving to deadline; managed guard SIGKILL with ExecStopPost pause. Prior eight native enrollment cases are reused, not rerun. Synthetic fixture clock/evidence are explicit and no real broker token is forwarded. These are disposable rehearsals, not fresh live evidence or an actual reboot. The exact pre-resume guard-kill race has lock-based mitigation but no targeted fault-injection test in this package; do not claim that race qualified.

No existing app sources, live databases, units, issuer keys, registry, default registration, production launcher or hard gate are modified. Only disposable transient guard units are started/killed/stopped. A candidate release is staged; it is not deployed. There is no live arm/apply/enrollment CLI. The new observer environment keys need exact wrapper/recovery/deployment review before a live installation. The independent guard adapter still rejects unmarked live databases.

Worker hook only records the paused boundary; actual LocalApproval signing and DisabledEnrollmentFlow enrollment still require a separate exact reviewed live seed/context plan. Final activation remains closed and requires external broker evidence, real session qualification and separate gate review.
