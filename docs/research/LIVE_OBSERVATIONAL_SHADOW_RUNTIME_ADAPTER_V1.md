# LIVE_OBSERVATIONAL_SHADOW_RUNTIME_ADAPTER_V1

## Scope

This is the bridge between the existing live production runtime and
`LIVE_OBSERVATIONAL_SHADOW_V1`.

It deliberately **does not** implement:

- ALL_3 calculation
- PCR/OI calculation
- futures OI classification
- moving ATM calculation
- option-chain lookup
- option candle acquisition
- broker order placement

Those values must come from the existing production engines.

## Processing contract

### 1. `on_new_all3`

Call immediately after a completed 5-minute checkpoint has produced a directional
ALL_3 state.

Inputs:

- session date
- exact completed-candle timestamp
- ALL_3 state
- spot at that checkpoint
- most recent prior directional ALL_3 state

A shadow observation is created only for a **new opposite directional ALL_3**.

Duplicate identity is deterministic:

`session_date + direction + candle1_timestamp`

A process restart therefore does not create a duplicate observation.

### 2. `on_candle2`

Call on the next completed 5-minute checkpoint for that observation.

The adapter performs only orchestration:

1. same target ALL_3 survived?
2. exact futures OI state present?
3. futures state supportive?
4. classify C1->C2 spot as `SPOT_LAG` / `SPOT_ALREADY_MOVED`

Support mapping is frozen to:

- bullish: `LONG_BUILDUP`, `SHORT_COVERING`
- bearish: `SHORT_BUILDUP`, `LONG_UNWINDING`

If the existing production engine uses different enum strings, normalize them in the
production wiring layer. Do not silently reinterpret them here.

### 3. `on_exact_option_resolved`

Called by the existing moving-ATM / instrument resolver.

No nearest-strike fallback is implemented.

### 4. `on_exact_next_minute_open`

Called only when the exact selected option's exact next-minute open is available.

No nearest-time fallback is implemented.

### 5. `on_option_minute`

Called for every completed 1-minute OHLC candle of the selected option while the
shadow trade is open.

The existing shadow engine manages:

- initial -5% stop
- BE arm at +5%
- trailing activation at +10%
- 3% trailing distance
- 15-minute maximum hold

No real or paper broker order is created.

## Important production wiring requirement

Do not patch `worker.py` blindly.

The repository's collector currently records market observations through
`record(engine, config_id, snapshot)`. The ALL_3/futures/ATM values needed by this
adapter may live in downstream analysis modules rather than directly in that collector.

Wire this adapter at the point where all of the normalized inputs are already available.

## Files written

The adapter writes only through the existing shadow audit store, normally:

`data/live-observation/shadow-v1/events.jsonl`

Ledger and daily summaries remain generated by the existing V1 CLI.
